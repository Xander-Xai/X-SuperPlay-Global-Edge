# ADR-0001: Local runtime architecture for the connection-capable client

**Status:** Proposed for milestone 0.2. This ADR does not change the 0.1
read-only release. The P13-002 read-only boundary in
[monorepo-boundaries.md](../monorepo-boundaries.md) remains in force until this
ADR is accepted and the security gates below are updated.

**Date:** 2026-10-27

## Context

The current desktop client is a read-only observer. It renders control-plane
evidence from the health API, keeps stale and unavailable states distinct from
health, and exposes no native commands or system-network mutations.

Milestone 0.2 requires the desktop client to become the normal entry point for
establishing and supervising connectivity. That is a new trust boundary: the
client will eventually start a transport process and mutate proxy, route, DNS,
or TUN state. The existing contracts deliberately forbid those actions, so the
architecture must be recorded and the gates must be updated explicitly rather
than weakened implicitly.

The roadmap is tracked in [PROJECT-ROADMAP.md](../../../PROJECT-ROADMAP.md) and
issue [#36](https://github.com/Xander-Xai/X-SuperPlay-Global-Edge/issues/36).

## Decision

Adopt four layers:

1. Desktop UI (React renderer).
2. Local controller (separate Rust process, bundled as a Tauri sidecar).
3. Managed network core (transport implementation).
4. System network integration (privileged helper where required).

```text
Renderer -> authenticated local IPC -> local controller -> core process
                                             |
                                             +-> privileged helper -> TUN/route/DNS
                                             +-> observer API (telemetry input)
```

The renderer never spawns processes, never receives long-lived credentials, and
never talks to the core or the privileged helper directly.

### Local controller as a separate process

- A small Rust binary under `apps/edge-desktop/controller/`, bundled as a Tauri
  sidecar and started by the desktop shell.
- It owns the core lifecycle, profile compilation, status, diagnostics, and
  state restoration.
- Keeping it out of the Tauri native shell preserves the current invariant that
  the webview host does not spawn arbitrary processes. The controller has its
  own reviewed process-spawning surface.
- The controller is the only component allowed to start or stop the core and to
  call the privileged helper.

### Core selection is deferred

This ADR does not select a core. A reproducible spike must compare a managed
multi-protocol core with directly supervising Xray, Hysteria2, and WireGuard.
The evaluation matrix covers protocol coverage, TUN/system-proxy support,
Windows behavior, upgrade model, binary size, license, provenance, crash
isolation, and observability.

Until that spike is recorded, no core is bundled or enabled by default.

### Privileged helper

- Only for operations that cannot run unprivileged: TUN device creation, route
  changes, DNS configuration, and their reverts.
- Fixed operation set; no generic shell and no arbitrary path access.
- Authenticates the controller separately and rejects unauthorized callers.
- Installed and removed by an explicit, reversible operator action.

## Ownership and trust boundaries

| Component | Owns | Must not |
| --- | --- | --- |
| Renderer | presentation and local view state | spawn processes, hold secrets, talk to the core or helper |
| Controller | lifecycle, profile compilation, status, diagnostics, recovery | accept unauthenticated IPC or expose arbitrary command execution |
| Core | transport data plane | mutate host network state outside the controller or helper |
| Privileged helper | TUN, route, and DNS operations | run inside the renderer or expose a generic shell |
| Observer API | evidence and health | be duplicated as a second runtime-state model |

## Local IPC contract

Minimum operations:

- `connect(profile_id)`, `disconnect()`, `status()`, `transports()`, and
  `diagnostics()` with bounded, redacted output.
- State transitions are explicit and idempotent.
- Response size, timeout, and concurrency are bounded.

Transport and authentication:

- A Windows named pipe with an ACL restricted to the current user is preferred;
  loopback HTTP is a fallback.
- A random per-install token is generated by the controller at first launch and
  stored in the Windows Credential Manager or an equivalent OS store.
- The desktop shell passes the token to the controller through an inherited
  handle or a protected environment variable; the renderer never sees it.
- Compare tokens in constant time, reject missing or invalid tokens without
  leaking detail, and rate-limit failures. Log bounded categories, never
  secrets.

## Transport state machine

```text
disabled -> starting -> ready -> degraded
                            \-> failed -> cooldown -> starting
                            \-> stopped
```

- `starting` has a bounded readiness deadline.
- `degraded` keeps the last-known-good transport while reporting the failure.
- `failed` requires an explicit or bounded automatic recovery policy.
- `cooldown` prevents restart storms.
- Every transition records a timestamp, a reason category, and a bounded
  evidence reference, never a secret.

## Failure and recovery

- Startup reconciliation detects stale proxy, route, DNS, or TUN state from a
  previous session and restores or reports it before accepting a connect
  request.
- Crash detection covers the core and controller, with a bounded restart policy.
- Clean shutdown restores system state.
- Failed upgrades and interrupted startups must not leave the machine
  half-connected.
- Recovery is operator-visible; no silent mutation.

## Security gates that must change before implementation

The following P13-002 assets are intentionally strict. They must be updated in a
reviewed PR, not bypassed:

1. `apps/edge-desktop/src/security.test.ts`: keep the renderer rule ("no native
   commands, no process spawning") and add a separate policy for the controller
   binary.
2. `scripts/ci/check-edge-desktop-boundary.py`: allow the controller and sidecar
   assets while continuing to forbid production and runtime paths.
3. `apps/edge-desktop/src-tauri/tauri.conf.json`: add the sidecar and only the
   capabilities the controller needs. The renderer capability list stays empty.
4. CI: add IPC authentication tests, unauthorized-caller rejection, state
   machine tests, and recovery tests using local fixtures only.

## Consequences

Positive:

- Clear privilege and crash boundaries.
- A renderer compromise does not directly grant process or network control.
- Each layer is independently testable.
- The core can change without rewriting the UI.

Negative and risks:

- A second process to package, sign, update, and monitor.
- IPC adds latency and an authentication surface.
- Sidecar lifecycle can race with the desktop shell.
- Code signing and updater work become prerequisites for distribution.

## Open questions

- Managed multi-protocol core versus direct supervision (spike).
- Named pipe versus loopback HTTP on Windows.
- Whether the privileged helper is a Windows service or an elevated one-shot.
- How the controller is signed and updated alongside the desktop app.
- Whether Linux and macOS are in scope. This ADR assumes Windows first.
